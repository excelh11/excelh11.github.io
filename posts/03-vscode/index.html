앞 글에서 파이썬 가상환경을 만들었습니다. 이제 그 환경에서 코드를 편하게 쓰고, 실행하고, 결과를 확인할 도구가 필요합니다. 이 글은 VS Code(Visual Studio Code) 를 설치하고, 파이썬 인터프리터와 주피터 커널을 가상환경에 정확히 연결하는 과정을 다룹니다.

로봇 개발에서 이 연결이 중요한 이유는 단순합니다. 편집기가 엉뚱한 파이썬을 바라보고 있으면, 아무리 패키지를 설치해도 ModuleNotFoundError가 계속 나고, 원인을 찾느라 시간을 허비합니다. “지금 어느 파이썬으로 실행 중인가”를 눈으로 확인할 수 있게 만드는 것이 이 글의 목표입니다.

이 글에서 다루는 것

  • VS Code가 무엇이고 왜 확장(Extension)이 필요한지
  • .deb 패키지로 설치하고 code 명령을 쓰는 방법
  • 파이썬 확장 설치와 인터프리터 선택
  • 주피터 노트북(.ipynb)에서 커널 선택과 셀 실행
  • 가상환경을 바꾸는 올바른 순서
  • 로봇 워크스페이스를 열 때의 실전 팁

명령은 어디에 입력하나요?

3편부터는 입력할 곳이 두 군데입니다.

입력할 곳 여는 방법 무엇을 입력하나
일반 터미널 Ctrl + Alt + T VS Code 설치, code 명령
VS Code 통합 터미널 VS Code에서 Ctrl + ` (백틱) 파이썬 확인, 패키지 설치
VS Code 편집기 화면 파일을 열고 ▶ 버튼 / Shift+Enter 코드 실행 (명령어 아님)
  • VS Code 안의 터미널도 일반 터미널과 같은 셸입니다. 다만 VS Code를 켠 폴더가 기준 위치가 됩니다.
  • (.venv) 가 보이면 그 창은 가상환경이 켜진 상태입니다(2편). 안 보이면 source .venv/bin/activate 로 먼저 켭니다.
  • VS Code에서 명령을 찾을 때는 Ctrl + Shift + P → 명령 팔레트에 이름을 입력합니다.

한눈에 보는 전체 흐름: 설치 → 확장 → 인터프리터 → 실행

3번(인터프리터 선택)이 이 글의 핵심입니다. 여기가 어긋나면 패키지를 설치해도 코드가 돌지 않습니다.

  1. 설치 — .deb 패키지로 VS Code 설치
  2. 확장 — Python, Jupyter 확장 설치
  3. 인터프리터 — Ctrl+Shift+P → Python: Select Interpreter → .venv/bin/python
  4. 실행 — .py는 실행 버튼, .ipynb는 커널 선택 후 셀 실행

1. VS Code는 “빈 틀”입니다

VS Code는 마이크로소프트가 오픈소스로 개발하는 소스 코드 편집기입니다. 윈도우·리눅스·macOS에서 모두 동작하고, 하나의 프로그램으로 파이썬, C++, JavaScript, YAML, 마크다운까지 다룹니다.

비결은 확장 기능(Extension) 입니다. VS Code 본체는 편집 기능만 있고, 언어별 기능(자동완성, 디버깅, 린트)은 확장을 설치해야 켜집니다.

확장 하는 일 로봇 개발에서
Python 파이썬 문법 지원, 실행, 디버깅, 인터프리터 선택 노드 스크립트 실행·디버깅
Jupyter .ipynb 노트북 편집·실행 센서 데이터 분석, 알고리즘 실험
Pylance 정적 타입 검사·자동완성 (Python 확장과 함께 설치됨) 대규모 코드 탐색

IDE(통합 개발 환경)라는 말을 쓰기도 하지만, 정확히는 “편집기 + 확장”입니다. 그래서 어떤 언어를 쓰든 시작은 “확장 설치”부터입니다.

2. 설치: .deb 패키지

우분투에서는 공식 .deb 패키지로 설치하는 것이 가장 깔끔합니다. .deb는 데비안/우분투 계열의 설치 패키지 형식입니다.

방법 A: 브라우저로 내려받아 설치

  1. https://code.visualstudio.com/download 접속
  2. Debian, Ubuntu 항목의 64 bit (AMD64) 클릭 → .deb 파일 다운로드
  3. 다운로드 폴더로 이동해 설치

⌨️ 입력 위치: 일반 터미널 — 다운로드 폴더로 이동 · $ 뒤에 입력하고 Enter

cd ~/Downloads
ls code_*.deb
sudo apt install ./code_*.deb

./를 꼭 붙이세요. apt install code_1.x.deb처럼 쓰면 apt가 저장소에서 패키지를 찾으려 해서 “Unable to locate package” 오류가 납니다. 경로를 명시하는 ./가 로컬 파일 설치의 표시입니다.

방법 B: 터미널에서 한 번에

⌨️ 입력 위치: 일반 터미널 — 다운로드 폴더로 이동 · $ 뒤에 입력하고 Enter

cd ~/Downloads
wget -O code.deb "https://go.microsoft.com/fwlink/?LinkID=760868"
sudo apt install ./code.deb

위 링크는 VS Code 공식 다운로드 페이지가 제공하는 Linux .deb(64비트) 링크입니다. 버전이 바뀌어 링크가 동작하지 않으면 방법 A로 진행하세요.

설치 중 물어보는 것

.deb 설치 과정에서 “Microsoft 저장소를 추가할까요?” 라는 질문이 나옵니다. 여기서 Yes를 선택하면 VS Code의 apt 저장소와 서명 키가 등록되어, 이후 sudo apt upgrade로 VS Code도 함께 업데이트됩니다.

예전에는 sudo dpkg -i 파일.deb → sudo apt -f install 두 단계를 써야 했습니다. 지금은 apt install ./파일.deb가 의존성까지 처리하므로 이 한 줄이면 됩니다. (dpkg -i는 의존성이 빠졌을 때 오류를 남기고 멈추는 경우가 있습니다.)

설치 확인:

⌨️ 입력 위치: 일반 터미널 · $ 뒤에 입력하고 Enter

code --version

3. code 명령으로 폴더 열기

VS Code의 가장 편한 기능 중 하나는 터미널에서 바로 폴더를 열 수 있다는 점입니다.

⌨️ 입력 위치: 일반 터미널 — 프로젝트 폴더에서 · $ 뒤에 입력하고 Enter

cd ~/robot
code .
  • .은 “현재 폴더”를 뜻합니다.
  • 폴더를 열면 VS Code 왼쪽 Explorer에 그 폴더의 파일 트리가 뜹니다.

로봇 프로젝트는 폴더 단위로 관리합니다. code ~/robot_ws처럼 워크스페이스 최상위 폴더를 열어야 파일 간 이동, 검색, Git 연동이 자연스럽게 동작합니다. 파일 하나만 열면 나중에 import 경로가 꼬입니다.

처음 열 때 나오는 “Trust” 창

폴더를 처음 열면 “Do you trust the authors of the files in this folder?” 라는 창이 뜹니다.

  • Yes, I trust the authors: 이 작업 공간의 자동 실행 기능(디버거, 태스크)을 허용
  • No: 제한 모드로 열림. 코드는 읽을 수 있지만 자동 실행 기능이 제한됩니다.

내가 만든 폴더라면 Yes를 선택하세요. No를 고르면 VS Code를 열 때마다 다시 물어봅니다.

4. 파이썬 확장 설치

  1. 왼쪽 아이콘 바에서 Extensions (블록 모양) 클릭
  2. 검색창에 Python 입력
  3. Microsoft가 배급하는 Python 확장 설치
  4. (같이 설치되는 Pylance도 그대로 두면 됩니다)

설치가 끝나면 .py 파일에서 자동완성과 오류 표시가 동작합니다.

5. 인터프리터 선택: 이 단계가 핵심입니다

VS Code가 파이썬 코드를 실행하려면 어떤 파이썬을 쓸지 알아야 합니다. 이를 인터프리터(interpreter) 라고 합니다.

VS Code 공식 문서에 실린 화면입니다. Python 3.10.5 ('venv': venv) … Recommended가 지금 폴더의 가상환경이고, 아래는 시스템·Conda 등 다른 인터프리터입니다. 5장에서 고르는 것이 바로 이 목록입니다. (출처: VS Code 공식 문서, CC BY 3.0)

※ VS Code 공식 문서의 예시 화면입니다. 화면의 경로(가상환경 폴더의 .venv 안 Scripts/python.exe, 윈도우 표기)와 파이썬 버전은 각자 사용하는 PC 환경에 따라 다릅니다 — 우분투에서는 ~/venv/robot_venv/bin/python처럼 보입니다.

선택하는 방법

  1. Ctrl + Shift + P → 명령 팔레트 열기
  2. Python: Select Interpreter 입력 후 선택
  3. 목록에서 ~/venv/robot_venv/bin/python (또는 Python 3.12.x ('robot_venv': venv)) 선택

목록에 안 보이면 Enter interpreter path… → Find… 로 ~/venv/robot_venv/bin/python을 직접 지정하면 됩니다.

가상환경이 목록에 나타나려면 VS Code를 열기 전에 터미널에서 활성화되어 있는 편이 확실합니다. VS Code는 현재 셸의 VIRTUAL_ENV를 참고해 자동으로 후보를 제시합니다.

확인

VS Code 오른쪽 아래 상태 표시줄에 선택된 인터프리터가 표시됩니다. 여기를 클릭하면 다시 선택할 수 있습니다.

Python 3.12.x ('robot_venv': venv)

인터프리터가 왜 이렇게 중요한가

⌨️ 입력 위치: VS Code 통합 터미널 (Ctrl+`) · $ 뒤에 입력하고 Enter

# VS Code의 통합 터미널에서
which python
python -c "import sys; print(sys.prefix)"

출력이 ~/venv/robot_venv를 가리키면 정상입니다. 이게 /usr/bin/python3로 나오면, VS Code가 시스템 파이썬으로 실행 중이라는 뜻이고, 방금 설치한 패키지를 못 찾습니다.

6. 첫 파이썬 파일 실행

  1. Explorer에서 폴더 우클릭 → New File… → hello.py
  2. 아래 코드 입력
import sys

print("Hello, robot!")
print("Python:", sys.version.split()[0])
print("Interpreter:", sys.executable)

파일을 만들고 코드를 저장하면 오른쪽 위에 ▷ Run Python File 버튼이 나타납니다. (출처: VS Code 공식 문서)

※ VS Code 공식 문서의 예시 화면입니다. 편집기 테마·글꼴·경로 표시는 각자 설정과 PC 환경에 따라 다를 수 있습니다.

실제 실행 결과입니다. 아래쪽 TERMINAL 탭에 Roll a dice!와 프롬프트가 이어서 찍힙니다. 실행에 쓴 파이썬 경로가 프롬프트 앞에 표시되는 것도 눈여겨보세요. (출처: VS Code 공식 문서)

※ VS Code 공식 문서의 예시 화면입니다. 프롬프트가 PS C:...> 같은 윈도우 파워셸 표기로 보이는 것은 운영체제에 따라 다르고, 우분투에서는 (robot_venv) user@robot-pc:~/hello$처럼 보입니다.

  1. 오른쪽 위 ▷ (Run Python File) 클릭 또는 Ctrl + F5

Interpreter 줄에 가상환경 경로가 찍히면 성공입니다.

sys.executable을 찍는 습관은 디버깅에 매우 유용합니다. “이 코드가 어느 파이썬으로 돌고 있는가”를 코드가 스스로 말해 주기 때문입니다. 로봇 코드의 로그 첫 줄에 이걸 넣어 두는 사람도 많습니다.

7. 주피터 노트북 사용하기

로봇 개발에서 주피터는 센서 데이터를 눈으로 확인할 때 강력합니다. 라이다 스캔을 그래프로 그리고, 카메라 프레임을 확인하고, 제어 파라미터를 바꿔 가며 결과를 비교하는 작업은 스크립트보다 노트북이 편합니다.

확장 설치

Extensions에서 Jupyter를 검색해 Microsoft의 Jupyter 확장을 설치합니다.

노트북 만들기

hello.ipynb를 열면 오른쪽 위에 Select Kernel이 뜹니다. 이것을 먼저 눌러야 합니다. (출처: VS Code 공식 문서)

※ VS Code 공식 문서의 예시 화면입니다. 커널 목록에 뜨는 파이썬 이름·버전은 각자 설치한 환경에 따라 다릅니다.

  1. Explorer에서 New File… → hello.ipynb
  2. 오른쪽 위 Select Kernel 클릭
  3. Python Environments 선택
  4. robot_venv 선택

커널(Kernel)은 노트북의 코드를 실제로 실행하는 백엔드입니다. 커널을 잘못 고르면 노트북에서 설치한 패키지를 못 찾습니다. 인터프리터와 커널은 별개로 선택된다는 점을 기억하세요.

실행

import numpy as np
print(np.__version__)

셀을 클릭하고 Shift + Enter 를 누르면 실행되고, 결과가 셀 아래에 표시됩니다.

위쪽 Run All로 전체 실행, 각 셀 왼쪽의 ▷로 한 셀만 실행합니다. 오른쪽 위에 지금 붙어 있는 커널(예: Python 3.11.x)이 표시됩니다. (출처: VS Code 공식 문서)

※ VS Code 공식 문서의 예시 화면입니다. 커널 이름(Python 3.11.x)과 경로는 각자 환경에 따라 다릅니다.

모듈이 없다고 나올 때

ModuleNotFoundError: No module named 'cv2'

이 오류는 “그 커널의 환경에 패키지가 없다”는 뜻입니다. 해결 순서는 다음과 같습니다.

  1. VS Code에서 Terminal → New Terminal (통합 터미널)
  2. 프롬프트에 (robot_venv)가 있는지 확인
  3. 설치

⌨️ 입력 위치: VS Code 통합 터미널 — .venv 가 켜진 상태 · $ 뒤에 입력하고 Enter

python -m pip install opencv-python
  1. 노트북에서 해당 셀 다시 실행 (필요하면 Restart Kernel)

브라우저에서 실행하는 Jupyter와 달리, VS Code 안의 노트북은 통합 터미널의 환경과 커널이 연결되어 있습니다. 그래서 “어디에 설치해야 하는지”가 눈에 보입니다.

8. 가상환경을 바꾸고 싶을 때

프로젝트마다 환경이 다르다면, 순서를 지켜야 합니다. VS Code는 시작할 때의 환경을 물고 있기 때문에, 켜 둔 채로 활성화만 바꾸면 반영되지 않습니다.

1. VS Code 종료
2. 터미널에서 기존 환경 deactivate
3. 사용할 환경 activate
4. 그 상태에서 code . 로 다시 열기
5. Select Interpreter / Select Kernel로 새 환경 확인

9. 알아 두면 좋은 설정

Ctrl + , 로 설정을 열고 검색해 바꿀 수 있습니다. (또는 settings.json 직접 편집)

설정 값 이유
Editor: Format On Save 켜기 저장할 때 자동 정렬
Files: Trim Trailing Whitespace 켜기 줄 끝 공백 제거 (diff 소음 감소)
Editor: Render Whitespace boundary 들여쓰기 오류를 눈으로 확인
Files: Exclude **/__pycache__, **/venv 검색·탐색에서 환경 폴더 숨김

venv 폴더를 검색 대상에서 빼면, Ctrl+Shift+F 검색 결과가 내 코드만 나와서 훨씬 깔끔합니다.

10. 로봇 개발에서 VS Code를 쓰는 지점

작업 VS Code에서 하는 법
ROS 2 파이썬 노드 작성 .py 파일 + Python 확장, 인터프리터를 ROS 2 환경에 맞춤
여러 파일에 걸친 심볼 찾기 F12(정의로 이동), Shift+F12(참조 찾기)
YAML 설정·launch 파일 편집 확장 없이도 문법 강조, 들여쓰기 확인이 쉬움
로그 분석 통합 터미널 + Terminator 병행
원격 로봇 PC에서 편집 Remote - SSH 확장으로 로봇 PC의 폴더를 직접 열기
Git 관리 소스 제어 탭에서 변경 확인·커밋 (터미널 git과 동일)

특히 Remote - SSH는 실무에서 자주 씁니다. 로봇 본체에 모니터를 붙이지 않고, 내 노트북에서 로봇 PC의 코드를 그대로 편집·실행할 수 있습니다.

11. 자주 겪는 문제

증상 원인 해결
code: command not found 설치 미완료 또는 PATH 미반영 설치 후 새 터미널에서 재시도
apt install code_x.deb 실패 ./ 누락 sudo apt install ./code_x.deb
인터프리터 목록에 venv가 없음 VS Code를 먼저 열었음 Enter interpreter path로 직접 지정
노트북에서 ModuleNotFoundError 커널이 다른 환경 Select Kernel → robot_venv
패키지 설치했는데 계속 오류 시스템 파이썬에 설치됨 통합 터미널에서 (venv) 확인 후 python -m pip install
Trust 창이 매번 뜸 No 선택 Yes 선택 또는 Workspace Trust 설정 변경
.ipynb가 실행 안 됨 Jupyter 확장 미설치 Jupyter 확장 설치 후 재시작

12. 정리

⌨️ 입력 위치: 일반 터미널 — 순서대로 · $ 뒤에 입력하고 Enter

# 설치
sudo apt install ./code_*.deb

# 폴더 열기
code .

# 인터프리터/커널 선택은 VS Code 안에서
# Ctrl+Shift+P → Python: Select Interpreter
# .ipynb 우측 상단 → Select Kernel → robot_venv
  • VS Code는 편집기이고, 기능은 확장으로 붙입니다.
  • Python 확장 + 인터프리터 선택, Jupyter 확장 + 커널 선택이 핵심 두 쌍입니다.
  • 환경을 바꿀 때는 “VS Code 종료 → deactivate → activate → 다시 열기” 순서를 지킵니다.

다음 글부터는 드디어 로봇 소프트웨어입니다. ROS 2 Jazzy를 우분투 24.04에 설치하고, 두 개의 노드가 실제로 메시지를 주고받는 것까지 확인합니다.

이 글에 나온 명령어·기호 풀이

표기 원래 말 / 읽는 법 하는 일
code — VS Code 실행 명령 (설치하면 자동 등록)
code . — 현재 폴더를 VS Code로 엽니다 (. = 현재 폴더)
code ~/.bashrc — 특정 파일을 VS Code로 엽니다
--version -- 는 긴 옵션 접두 버전만 확인하고 종료
sudo apt install ./code_*.deb — 현재 폴더의 .deb 파일로 설치
./ — 현재 폴더의 파일을 지목
* 와일드카드 아무 글자나 (예: code_*.deb = code_ 로 시작하는 모든 deb)
cd change directory 폴더 이동
Ctrl+Shift+P — VS Code 명령 팔레트 (이름으로 기능 찾기)
Ctrl+` — VS Code 통합 터미널 열기/닫기
Shift+Enter — 노트북 셀 실행 후 다음 셀로 이동
Ctrl+Enter — 노트북 셀만 실행 (이동 없음)
python -m pip install opencv-python -m = module 그 인터프리터의 pip로 설치 (어느 파이썬인지 확실해짐)
ModuleNotFoundError — “그 모듈이 이 파이썬 환경에 없다”는 오류
(.venv) / ('robot_venv': venv) — VS Code가 가상환경을 쓰고 있다는 표시

VS Code에서 파일 실행은 명령어가 아니라 오른쪽 위 ▶ 버튼으로 합니다. 버튼이 없으면 .py 파일을 열고 한 번 저장(Ctrl+S)하면 나타납니다.
