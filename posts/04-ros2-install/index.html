여기까지 왔다면 운영체제와 개발 도구가 준비됐습니다. 이제 로봇 소프트웨어의 본체인 ROS 2를 설치합니다.

이 글은 Ubuntu 24.04 LTS에 ROS 2 Jazzy Jalisco를 공식 배포판(deb 패키지) 방식으로 설치하고, 두 개의 노드가 실제로 메시지를 주고받는 것까지 확인하는 전 과정을 다룹니다. 설치 명령은 2026년 기준 ROS 공식 문서의 절차를 그대로 따르며, 예전 튜토리얼과 달라진 부분(GPG 키 수동 등록 → ros2-apt-source 패키지)도 함께 설명합니다.

이 글에서 다루는 것

  • ROS 2와 배포판(Jazzy)의 개념, 우분투 버전과의 짝
  • locale, universe 저장소, ROS 2 apt 저장소 준비

  • 자주 막히는 지점과 해결

명령은 어디에 입력하나요?

ROS 2 설치 명령은 모두 일반 터미널에서 입력합니다.

여는 방법: Ctrl + Alt + T (여러 개 필요하면 Ctrl + Shift + T 로 탭을 늘리거나 새 창을 엽니다)

이 글에서 쓰는 터미널 구성

이름 여는 법 역할
설치용 터미널 Ctrl+Alt+T 2~4장의 설치·환경 설정 명령
터미널 1 새 창 talker 실행 (계속 떠 있어야 함)
터미널 2 새 창 listener 실행 (계속 떠 있어야 함)
터미널 3 새 창 ros2 topic list 같은 확인 명령
  • ros2 명령은 source /opt/ros/jazzy/setup.bash 를 한 창에서만 동작합니다. 새 창을 열 때마다 다시 입력해야 합니다(5편에서 자동화).
  • 실행 중인 창(talker·listener)은 닫지 말고 그대로 두고, 다른 창에서 다음 명령을 칩니다.
  • 복사는 Ctrl+Shift+C, 붙여넣기는 Ctrl+Shift+V 입니다.

한눈에 보는 전체 흐름: 로케일 → 저장소 → 설치 → 환경 → 검증

설치만 하고 끝내지 말고 5번(두 노드 통신)까지 확인해야 설치가 끝난 것입니다.

1. ROS 2가 무엇이고, 왜 Jazzy인가

ROS 2(Robot Operating System 2) 는 운영체제가 아니라 로봇 소프트웨어를 만들기 위한 미들웨어 + 도구 모음입니다. 핵심 발상은 이렇습니다.

로봇을 하나의 거대한 프로그램으로 만들지 말고, 기능별로 잘게 나눈 프로그램(노드) 들이 정해진 방식으로 메시지를 주고받게 하자.

카메라를 읽는 노드, 라이다를 처리하는 노드, 경로를 계획하는 노드, 모터를 돌리는 노드를 각각 따로 만들고 서로 통신하게 하면, 하나를 바꿔도 나머지가 그대로 동작합니다. ROS 2는 그 통신 규칙(토픽·서비스·액션), 실행 도구(ros2 명령), 시각화 도구(RViz, rqt), 빌드 시스템(colcon)을 제공합니다.

배포판과 우분투의 짝

ROS 2는 1년마다 새 배포판을 내고, 짝수 해에 나오는 버전이 LTS(장기 지원) 입니다.

배포판 공개 지원 종료 대응 우분투
Humble Hawksbill 2022년 5월 2027년 5월 Ubuntu 22.04
Jazzy Jalisco 2024년 5월 2029년 5월 Ubuntu 24.04
Kilted Kaiju 2025년 5월 2026년 11월 Ubuntu 24.04

공식 플랫폼 정의(REP 2000)에서 Jazzy의 Tier 1 플랫폼은 Ubuntu 24.04 (amd64, arm64) 와 Windows 10입니다. Tier 1은 “지속적으로 테스트되고, 버그가 우선적으로 수정되는” 등급이므로, 로봇을 처음 시작한다면 Tier 1 조합을 쓰는 것이 가장 안전합니다.

정리: Ubuntu 24.04 LTS + ROS 2 Jazzy는 2029년 5월까지 함께 가는 조합입니다. 이 짝을 벗어나면 패키지가 없거나 의존성이 깨지는 일이 생깁니다.

설치 방법은 세 가지

방법 특징 추천
deb 패키지(바이너리) apt로 설치, 즉시 사용 ✅ 처음 시작
소스 빌드 커스터마이징 가능, 오래 걸림 특수 요구가 있을 때
Docker 이미지 호스트 오염 없음, 재현성 서버·배포

이 글은 공식 문서가 “권장”으로 표시하는 deb 패키지 설치를 다룹니다.

2. 설치 전 시스템 준비

2-1. locale 설정 (UTF-8)

ROS 2는 문자열 처리에 UTF-8 로케일을 요구합니다. 먼저 현재 상태를 확인합니다.

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

locale

LANG= 값이 en_US.UTF-8처럼 UTF-8을 가리키면 그대로 진행해도 됩니다. 최소 환경(도커 컨테이너 등)에서 POSIX로만 되어 있다면 아래를 실행합니다.

sudo apt update && sudo apt install locales
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8

locale   # 다시 확인

sudo update-locale은 시스템 기본값을, export는 현재 셸에만 적용합니다. 두 줄이 함께 있는 이유입니다.

2-2. universe 저장소 활성화

ROS 2 패키지가 의존하는 도구들이 우분투의 universe(커뮤니티 패키지) 저장소에 있습니다.

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

sudo apt install software-properties-common
sudo add-apt-repository universe

2-3. ROS 2 apt 저장소 등록 (현재 공식 방식)

예전 문서에는 GPG 키를 직접 내려받아 /usr/share/keyrings에 넣고 sources.list.d/ros2.list를 만드는 절차가 있었습니다. 지금 공식 문서는 이 과정을 패키지 하나로 대신합니다. ros2-apt-source 패키지가 저장소 설정과 서명 키를 알아서 구성하고, 이후 저장소 설정이 바뀌어도 자동으로 갱신해 줍니다.

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

sudo apt update && sudo apt install curl -y

export ROS_APT_SOURCE_VERSION=$(curl -fsSL -o /dev/null -w '%{url_effective}' https://github.com/ros-infrastructure/ros-apt-source/releases/latest | awk -F/ '{print $NF}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb

명령이 길어 보이지만 하는 일은 단순합니다.

부분 의미
curl -fsSL -o /dev/null -w '%{url_effective}' .../releases/latest 최신 릴리스로 리다이렉트된 최종 URL만 읽어 옴
awk -F/ '{print $NF}' 그 URL의 마지막 조각(태그 이름)만 추출
$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}}) 현재 우분투 코드네임(noble)을 읽어 파일 이름을 완성
sudo dpkg -i /tmp/ros2-apt-source.deb 내려받은 설정 패키지 설치

💡 예전 방식(수동 GPG 키)을 쓰는 튜토리얼도 여전히 많습니다. 두 방식을 동시에 적용하면 저장소가 중복 등록되어 apt update에 경고가 쌓일 수 있으니, 하나만 쓰세요. 이미 예전 방식으로 등록해 두었다면 /etc/apt/sources.list.d/ros2.list를 지우고 위 방식을 쓰는 편이 깔끔합니다.

2-4. 개발 도구 (선택)

ROS 2 패키지를 직접 빌드하거나 개발할 계획이라면 설치합니다.

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

sudo apt update && sudo apt install ros-dev-tools

⚠️ Ubuntu 24.04 주의사항: apt 소스에 noble만 있고 noble-updates, noble-backports가 빠져 있으면 ros-dev-tools 설치 시 의존성 충돌이 날 수 있습니다. 공식 문서가 안내하는 확인 방법은 다음과 같습니다.

grep Suites /etc/apt/sources.list.d/ubuntu.sources

출력에 noble-updates, noble-backports가 없다면 해당 줄을 아래처럼 고친 뒤 다시 진행합니다.

Suites: noble noble-updates noble-backports

sudo apt clean && sudo apt update && sudo apt full-upgrade -y

3. ROS 2 Jazzy 설치

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

sudo apt update
sudo apt upgrade
sudo apt install ros-jazzy-desktop
  • sudo apt upgrade: ROS 2 패키지는 최신 우분투 시스템을 기준으로 빌드되므로, 설치 전 시스템을 최신으로 맞추라는 것이 공식 권장 사항입니다.
  • ros-jazzy-desktop: ROS, RViz, 데모, 튜토리얼이 포함된 권장 설치입니다.

desktop vs ros-base

패키지 포함 언제
ros-jazzy-desktop 통신 라이브러리 + GUI 도구(RViz, rqt) + 데모·튜토리얼 학습·개발 PC (권장)
ros-jazzy-ros-base 통신 라이브러리 + CLI 도구만 (GUI 없음) 로봇 본체, 서버, 임베디드

로봇 본체에 설치할 때는 ros-base로 용량을 줄이고, 개발 PC에는 desktop을 쓰는 구성이 일반적입니다.

설치에는 환경에 따라 수 GB의 다운로드와 수 분~수십 분이 걸립니다.

4. 환경 설정: source 한 줄의 의미

설치가 끝났다고 ros2 명령이 바로 되는 것은 아닙니다. 새 터미널마다 다음을 실행해야 합니다.

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

source /opt/ros/jazzy/setup.bash

setup.bash는 현재 셸에 ROS 2 관련 환경변수를 등록합니다. 대표적으로:

  • PATH: ros2 실행 파일 위치
  • PYTHONPATH: ROS 2 파이썬 패키지(rclpy 등) 위치
  • AMENT_PREFIX_PATH: 패키지 탐색 경로
  • LD_LIBRARY_PATH: 공유 라이브러리 경로

확인:

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

printenv | grep -i ros
ros2 --help

ROS_DISTRO=jazzy가 보이면 정상입니다.

💡 매 터미널마다 입력하기 번거롭다면 ~/.bashrc에 넣어 자동화합니다. 정확한 방법과 주의점은 다음 글(터미널·.bashrc)에서 자세히 다룹니다.

echo "source /opt/ros/jazzy/setup.bash" >> ~/.bashrc
source ~/.bashrc

5. 설치 검증: talker와 listener

ROS 2의 정상 동작은 두 노드가 메시지를 주고받는 것으로 확인합니다. 공식 문서는 C++ talker와 Python listener 조합을 안내합니다. 이렇게 하면 C++ API와 Python API가 둘 다 정상이라는 것을 한 번에 확인할 수 있습니다.

터미널 1: talker

⌨️ 입력 위치: 터미널 1 — talker 를 띄우는 창 · $ 뒤에 입력하고 Enter

source /opt/ros/jazzy/setup.bash
ros2 run demo_nodes_cpp talker

[INFO] [talker]: Publishing: 'Hello World: 1'
[INFO] [talker]: Publishing: 'Hello World: 2'
...

터미널 2: listener

⌨️ 입력 위치: 터미널 2 — listener 를 띄우는 창 (터미널 1은 그대로 둠) · $ 뒤에 입력하고 Enter

source /opt/ros/jazzy/setup.bash
ros2 run demo_nodes_py listener

[INFO] [listener]: I heard: [Hello World: 1]
[INFO] [listener]: I heard: [Hello World: 2]
...

한쪽이 Publishing, 다른 쪽이 I heard를 출력하면 설치 성공입니다.

두 터미널 모두에서 source를 해야 합니다. 셸은 터미널마다 독립이기 때문입니다(0편). “listener가 아무것도 못 받는다”의 가장 흔한 원인이 이것입니다.

ros2 run turtlesim turtlesim_node를 실행하면 뜨는 실제 창입니다. talker/listener 대신 눈으로 확인할 수 있는 노드라 설치 검증에 자주 씁니다. (출처: ROS 2 공식 문서, CC BY 4.0)

발행자는 받는 사람을 모릅니다. 토픽 이름만 같으면 연결됩니다(1:N, 비동기). (출처: ROS 2 공식 문서 Understanding topics, CC BY 4.0)

통신 구조를 눈으로 보기

세 번째 터미널에서:

⌨️ 입력 위치: 터미널 3 — 확인용 · $ 뒤에 입력하고 Enter

source /opt/ros/jazzy/setup.bash
ros2 topic list
ros2 topic echo /chatter

/chatter 토픽에 메시지가 흐르는 것을 직접 볼 수 있습니다. GUI로 보고 싶다면:

⌨️ 입력 위치: 터미널 3 · $ 뒤에 입력하고 Enter

rqt_graph

talker → /chatter → listener의 연결이 그래프로 표시됩니다.

6. 설치 후 알아 둘 것

6-1. 여러 대의 로봇이 같은 네트워크에 있을 때

ROS 2는 기본적으로 같은 네트워크의 모든 ROS 2 노드를 서로 발견합니다. 실습실이나 연구실처럼 여러 사람이 같은 공유기를 쓴다면, 내 로봇 명령이 다른 사람 노드에 보이고 그 반대도 마찬가지입니다.

이를 막는 것이 ROS_DOMAIN_ID입니다. 같은 값을 가진 노드끼리만 통신합니다.

⌨️ 입력 위치: 터미널 — 도메인 번호를 바꿔 볼 때 · $ 뒤에 입력하고 Enter

export ROS_DOMAIN_ID=13

기본값은 0이고, 안전하게 쓸 수 있는 범위는 0~101입니다(리눅스의 임시 포트 범위와 겹치지 않는 구간). 자세한 원리와 설정은 다음 글에서 다룹니다.

6-2. 제거와 재설치

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

sudo apt remove '~nros-jazzy-*' && sudo apt autoremove

저장소 설정까지 지우려면:

sudo apt remove ros2-apt-source
sudo apt update
sudo apt autoremove
sudo apt upgrade

설치가 꼬였을 때 “일단 지우고 다시 깔기”가 가능한 것이 바이너리 설치의 장점입니다.

6-3. GUI 도구가 안 뜰 때

RViz나 rqt가 실행되지 않는 경우, 대부분 그래픽 드라이버 또는 원격 접속 환경 문제입니다.

  • SSH로 접속한 상태라면 GUI가 뜨지 않는 것이 정상입니다(X 포워딩 필요).
  • NVIDIA 드라이버 설치 후에는 재부팅이 필요할 수 있습니다.
  • ros2 run rviz2 rviz2로 직접 실행해 오류 메시지를 확인하세요.

7. 자주 막히는 지점

증상 원인 해결
ros2: command not found source 안 함 새 터미널마다 source /opt/ros/jazzy/setup.bash
E: Unable to locate package ros-jazzy-desktop 저장소 미등록 또는 apt update 안 함 ros2-apt-source 설치 후 sudo apt update
apt update에 GPG/서명 오류 키·저장소 중복 또는 만료 예전 ros2.list 제거 후 재등록
talker는 뜨는데 listener가 못 받음 한쪽만 source / 도메인 ID 불일치 두 터미널 모두 source, echo $ROS_DOMAIN_ID 비교
ros-dev-tools 설치 중 의존성 충돌 noble-updates/noble-backports 누락 ubuntu.sources의 Suites 수정 후 full-upgrade
locale 경고 UTF-8 아님 2-1 절차 수행
설치가 중간에 멈춤 디스크 부족 df -h로 여유 공간 확인 (수 GB 필요)

8. 정리

⌨️ 입력 위치: 터미널 — 설치용 · $ 뒤에 입력하고 Enter

# 1) 시스템 준비
sudo apt update && sudo apt install locales curl
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
sudo apt install software-properties-common
sudo add-apt-repository universe

# 2) ROS 2 저장소 등록 (공식 방식)
export ROS_APT_SOURCE_VERSION=$(curl -fsSL -o /dev/null -w '%{url_effective}' https://github.com/ros-infrastructure/ros-apt-source/releases/latest | awk -F/ '{print $NF}')
curl -L -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb

# 3) 설치
sudo apt update && sudo apt upgrade
sudo apt install ros-jazzy-desktop

# 4) 환경 설정
source /opt/ros/jazzy/setup.bash
  • 배포판은 우분투 버전과 짝이 맞아야 합니다: Ubuntu 24.04 ↔ ROS 2 Jazzy.
  • 저장소 등록은 이제 ros2-apt-source 패키지로 처리합니다.
  • 설치 검증은 talker/listener, 그리고 rqt_graph로 구조 확인.
  • 여러 로봇이 같은 네트워크에 있다면 ROS_DOMAIN_ID를 반드시 설정합니다.

다음 글에서는 source를 매번 치지 않아도 되게 만드는 .bashrc, 반복 명령을 줄이는 alias, 그리고 네트워크 격리의 핵심인 ROS_DOMAIN_ID 를 다룹니다.

이 글에 나온 명령어·기호 풀이

표기 원래 말 / 읽는 법 하는 일
locale — 현재 언어·인코딩 설정을 보여 줍니다
sudo locales 설치 — 로케일 도구 설치
sudo locale-gen ko_KR.UTF-8 generate 해당 로케일을 생성
sudo update-locale LANG=ko_KR.UTF-8 — 기본 언어 값을 파일에 등록
sudo add-apt-repository universe — universe 저장소를 채널에 추가
curl — 인터넷에서 파일을 받는 도구
-s (--silent) — 진행 표시를 숨깁니다
-S (--show-error) — 오류는 그래도 보여 줍니다
-L (--location) — 이동(리다이렉트) 주소를 따라갑니다
-o 파일 (--output) — 받은 내용을 파일로 저장
./ros2-apt-source_*.deb — 받은 설치 파일을 현재 폴더에서 설치
sudo apt install ros-jazzy-desktop — ROS 2 본체 + GUI 도구 설치
-y yes 확인 질문에 자동 yes
source /opt/ros/jazzy/setup.bash — ROS 2 환경변수(PATH 등)를 이 창에 등록
ros2 run 패키지 실행파일 — 노드(=프로그램)를 실행
ros2 topic list — 지금 흐르는 토픽 목록
ros2 topic echo /chatter — 그 토픽에 오가는 내용을 출력
printenv | grep -i ros — 환경변수 중 ros 가 든 것만 출력
export ROS_DOMAIN_ID=13 — 통째 번호(도메인)를 이 창에 지정
~nros-jazzy-* — ros-jazzy- 로 시작하는 패키지 전체를 뜻하는 정규식
autoremove — 필요 없어진 의존 패키지까지 정리
rqt_graph — 노드·토픽 연결을 그림으로 보여 주는 도구

ros2: command not found 는 “이 창에 ROS 2 환경이 등록되지 않았다”는 뜻입니다. source /opt/ros/jazzy/setup.bash 를 입력하거나 새 창을 열면 해결됩니다.
