ROS 2를 설치했으니 이제 명령어로 로봇을 움직여 봅니다. 이 글은 ROS 2의 네 가지 핵심 개념 — 노드, 서비스, 토픽, 액션 — 을 터틀심(turtlesim) 이라는 학습용 거북이 시뮬레이터로 하나씩 확인합니다.

터틀심은 실제 로봇이 아니라 화면 속 거북이지만, 구조는 실제 로봇과 같습니다. 여기서 익힌 명령이 그대로 자율주행 로봇, 로봇팔, 드론의 제어에 쓰입니다.

이 글에서 다루는 것

  • 터틀심 실행과 키보드 조종
  • 노드: 실행 단위, 목록·정보 확인
  • 서비스: 요청-응답, 타입 확인, 호출
  • 토픽: 발행-구독, cmd_vel로 주행 명령 보내기
  • 액션: 목표-피드백-결과, 회전 목표 보내기
  • 네임스페이스와 도메인의 차이
  • 세 통신 방식의 비교와 실제 로봇에서의 대응

명령은 어디에 입력하나요?

6편은 터미널을 두 개 이상 띄워 놓고 진행합니다.

이름 여는 법 역할 주의
터미널 1 (시뮬레이터) Ctrl+Alt+T ros2 run turtlesim turtlesim_node 끄지 말고 계속 띄워 둡니다
터미널 2 (명령용) 새 창 ros2 node/topic/service/action ... 이 글의 대부분 명령
터미널 3 (조종용, 선택) 새 창 ros2 run turtlesim turtle_teleop_key 이 창에서만 방향키가 먹습니다
  • 터미널 1에서 거북이 창이 뜨고 로그가 계속 흐릅니다. 그 창에 다른 명령을 치면 안 됩니다 (실행 중이라 입력이 먹지 않습니다).
  • 새 창마다 ROS 2 환경이 필요합니다. .bashrc 를 설정했다면(5편) 자동으로 켜지고, 아니라면 source /opt/ros/jazzy/setup.bash 를 먼저 입력합니다.
  • 값이 {x: 2.0, y: 2.0} 처럼 중괄호로 들어가는 명령은 따옴표까지 그대로 복사해야 합니다.
  • 복사는 Ctrl+Shift+C, 붙여넣기는 Ctrl+Shift+V 입니다.

한눈에 보는 전체 흐름: 실행 → 노드 → 토픽 → 서비스 → 액션

“무엇이 있나”(노드)에서 “어떻게 시키나”(토픽 → 서비스 → 액션)로 넘어가는 순서입니다.

  1. 터틀심 실행 — ros2 run turtlesim turtlesim_node
  2. 노드 확인 — ros2 node list, ros2 node info /turtlesim
  3. 토픽 — ros2 topic list / echo / pub
  4. 서비스 — ros2 service call
  5. 액션 — ros2 action send_goal ... --feedback

1. 터틀심 시작하기

준비

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

source /opt/ros/jazzy/setup.bash

터틀심이 설치되어 있는지 확인:

ros2 pkg executables turtlesim

turtlesim draw_square
turtlesim mimic
turtlesim turtle_teleop_key
turtlesim turtlesim_node

없다면 설치합니다.

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

sudo apt update
sudo apt install ros-jazzy-turtlesim

실행

터미널 1 — 시뮬레이터:

⌨️ 입력 위치: 터미널 1 — 시뮬레이터 (끄지 말 것) · $ 뒤에 입력하고 Enter

ros2 run turtlesim turtlesim_node

[INFO] [turtlesim]: Starting turtlesim with node name /turtlesim
[INFO] [turtlesim]: Spawning turtle [turtle1] at x=[5.544445], y=[5.544445], theta=[0.000000]

여기서 읽을 정보가 세 가지 있습니다. 노드 이름은 /turtlesim, 거북이 이름은 turtle1, 시작 자세는 x=5.544445, y=5.544445, theta=0. 이 값들은 뒤에서 서비스·토픽 이름에 그대로 등장합니다.

파란 배경의 이 창이 시뮬레이터입니다. 이 창은 끄지 말고 그대로 두고, 나머지 명령은 다른 터미널에서 칩니다. (출처: ROS 2 공식 문서, CC BY 4.0)

터미널 3 — 키보드 조종:

⌨️ 입력 위치: 터미널 3 — 이 창에서 방향키 · $ 뒤에 입력하고 Enter

ros2 run turtlesim turtle_teleop_key

터미널 3을 활성 창으로 선택한 상태에서 방향키를 누르면 거북이가 움직이고, 지나간 자리에 선이 그려집니다.

💡 방향키를 한 번 누르면 짧게 움직이고 멈춥니다. 버그가 아니라 의도된 동작입니다. 실제 로봇에서 조종 신호가 끊겼는데 계속 달리면 위험하기 때문에, “명령이 계속 들어오는 동안만 움직이는” 방식이 기본입니다.

키 조작은 두 종류입니다.

키 동작
방향키 전진/후진/좌회전/우회전 (연속 주행 명령)
G B V C D E R T 지정된 방향으로 절대 회전(액션 목표 전송)
F 진행 중인 회전 목표 취소

이 키들은 실행 시 터미널에 안내가 표시됩니다. 8개의 회전 키는 “절대 방향”을 목표로 보내고, F는 그 목표를 중간에 취소합니다. 뒤에서 보겠지만 취소가 가능하다는 점이 액션의 핵심 특징입니다.

2. 노드(Node): 실행 단위

노드가 뭔가요

노드는 ROS 2에서 하나의 기능을 담당하는 실행 프로그램입니다. 터틀심에서는 turtlesim_node가 노드이고, 키보드 입력을 받아 명령을 보내는 turtle_teleop_key도 노드입니다.

패키지(package)와 노드(node)의 관계는 “묶음”과 “실행 파일” 의 관계입니다. turtlesim 패키지 안에 turtlesim_node, turtle_teleop_key, draw_square, mimic 네 개의 실행 파일(노드)이 들어 있습니다. 패키지는 배포 단위, 노드는 실행 단위입니다.

목록 보기

터미널 3을 열고:

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

source /opt/ros/jazzy/setup.bash
ros2 node list

/teleop_turtle
/turtlesim

지금 실행 중인 노드가 두 개라는 것을 알 수 있습니다. (윈도우의 작업 관리자와 비슷한 역할입니다.)

노드 정보 보기

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 node info /turtlesim

/turtlesim
  Subscribers:

  Publishers:

    /turtle1/set_pen: turtlesim/srv/SetPen
    /turtle1/teleport_absolute: turtlesim/srv/TeleportAbsolute
    /turtle1/teleport_relative: turtlesim/srv/TeleportRelative
    ...
  Action Servers:
    /turtle1/rotate_absolute: turtlesim/action/RotateAbsolute

이 한 화면에 ROS 2의 전체 구조가 들어 있습니다.

항목 의미
Subscribers 이 노드가 받는 토픽 (/turtle1/cmd_vel = 주행 명령)
Publishers 이 노드가 내보내는 토픽 (/turtle1/pose = 현재 자세)
Service Servers 이 노드가 응답하는 서비스
Action Servers 이 노드가 수행하는 액션

로봇 디버깅의 절반은 이 명령으로 시작합니다. “센서 노드가 값을 내보내고 있는가?”, “제어 노드가 그 토픽을 구독하고 있는가?”를 한 번에 볼 수 있기 때문입니다.

3. 서비스(Service): 요청하면 즉답

개념

서비스는 클라이언트가 요청(Request)을 보내면 서버가 응답(Response)을 돌려주는 1:1 동기 통신입니다. 전화 통화에 비유할 수 있습니다. 묻고, 답을 받고, 끝납니다.

  • 한 번의 요청에 한 번의 응답
  • 응답이 올 때까지 기다림
  • 상태를 계속 흘려보내는 용도로는 부적합

목록과 타입

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 service list

ros2 service list -t      # 타입까지 함께

/clear [std_srvs/srv/Empty]
/kill [turtlesim/srv/Kill]
/reset [std_srvs/srv/Empty]
/spawn [turtlesim/srv/Spawn]
/turtle1/set_pen [turtlesim/srv/SetPen]
/turtle1/teleport_absolute [turtlesim/srv/TeleportAbsolute]
/turtle1/teleport_relative [turtlesim/srv/TeleportRelative]

특정 서비스의 타입만 확인:

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 service type /turtle1/teleport_absolute

turtlesim/srv/TeleportAbsolute

타입의 구조 보기

서비스를 호출하려면 어떤 값을 넣어야 하는지 알아야 합니다.

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 interface show turtlesim/srv/TeleportAbsolute

float32 x
float32 y
float32 theta
---

--- 위쪽이 요청, 아래쪽이 응답입니다. 이 서비스는 x, y, theta를 보내고, 응답은 비어 있습니다(성공/실패 값조차 없음).

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 interface show turtlesim/srv/Spawn

float32 x
float32 y
float32 theta
string name # Optional. A unique name will be created and returned if this is empty
---
string name

이번엔 응답이 있습니다 — 새로 만들어진 거북이의 이름을 돌려줍니다.

--- 세 줄(대시 3개)이 요청/응답의 경계입니다. 이 규칙은 서비스 정의 파일(.srv)의 표준 문법입니다.

호출해 보기

절대 좌표로 순간이동:

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 service call /turtle1/teleport_absolute turtlesim/srv/TeleportAbsolute "{x: 2.0, y: 2.0, theta: 1.57}"
  • {...} 안의 값은 YAML 문법입니다.
  • theta는 라디안입니다. 1.57 ≈ 90°(위쪽).
  • 이 서비스는 이동 경로를 그리지 않고 순간이동합니다.

거북이 추가 생성:

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 service call /spawn turtlesim/srv/Spawn "{x: 2.0, y: 2.0, theta: 0.2, name: ''}"

requester: making request: turtlesim.srv.Spawn_Request(x=2.0, y=2.0, theta=0.2, name='')
response:
turtlesim.srv.Spawn_Response(name='turtle2')

name을 비워 두면 자동으로 turtle2가 만들어집니다. 이제 서비스 목록에 turtle2/...가 추가된 것을 볼 수 있습니다.

명령으로 치기 번거로우면 rqt → Plugins → Services → Service Caller에서 서비스를 고르고 값을 넣어 Call을 누르면 됩니다. 필드 구조(이름·타입)를 눈으로 확인할 수 있어 처음 배울 때 특히 유용합니다. (출처: ROS 2 공식 문서, CC BY 4.0)

(출처: ROS 2 공식 문서, CC BY 4.0)

화면 지우기 / 초기화:

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 service call /clear std_srvs/srv/Empty
ros2 service call /reset std_srvs/srv/Empty

Empty 타입은 요청도 응답도 없는 서비스입니다. ---만 있는 구조를 떠올리면 됩니다.

💡 긴 명령은 Tab 자동완성을 쓰세요. ros2 service call /turtle1/tele<Tab>까지 치면 타입과 필드 구조까지 자동으로 채워집니다.

4. 로봇의 자세: x, y, theta와 라디안

teleport_absolute에 x, y, theta를 넣는 이유를 이해하면 로봇 제어가 쉬워집니다.

평면에서 움직이는 로봇의 상태는 세 값으로 완전히 표현됩니다.

값 의미
x 가로 위치
y 세로 위치
theta 방향(자세) — x축 기준으로 반시계 방향 회전 각도

이 세 값을 자세(pose) 라고 부릅니다. 로봇공학에서 위치(position)와 자세(orientation)를 합친 개념입니다.

왜 도(degree)가 아니라 라디안인가

로봇 소프트웨어는 각도를 라디안(radian) 으로 다룹니다. 계산이 간단해지기 때문입니다. 호의 길이 = 반지름 × 각도(라디안)처럼, 회전과 이동이 곱셈 하나로 연결됩니다.

도(degree) 라디안
0° 0
90° π/2 ≈ 1.571
180° π ≈ 3.142
270° 3π/2 ≈ 4.712
360° 2π ≈ 6.283

변환은 간단합니다.

import math

def deg_to_rad(deg):
    return deg * math.pi / 180.0

def rad_to_deg(rad):
    return rad * 180.0 / math.pi

print(deg_to_rad(90))     # 1.5707963267948966
print(rad_to_deg(3.14))   # 179.9087476710785

⚠️ 라디안에서 각도는 2π를 주기로 반복됩니다. theta = 0과 theta = 6.283은 같은 방향입니다. 제어 코드를 짤 때 이 주기성을 고려하지 않으면 “180° 돌라고 했는데 540° 도는” 문제가 생깁니다. 실제 로봇 코드에서는 각도 차이를 -π ~ π 범위로 정규화(normalize)하는 함수를 거의 항상 함께 씁니다.

차동 구동 로봇의 제약

터틀심의 거북이는 차동 구동(differential drive) 로봇을 단순화한 모델입니다. 양쪽 바퀴의 속도 차이로 방향을 바꾸는 방식으로, 자동차와 비슷합니다.

  • 제자리에서 방향만 바꿀 수 없습니다. 앞으로 가면서(또는 뒤로 가면서) 회전해야 합니다.
  • 그래서 “지금 위치에서 목표 위치까지”는 직진 + 회전의 조합으로 만들어야 합니다.
  • 이 제약이 있는 로봇을 논홀로노믹(non-holonomic) 이라고 부릅니다.

반대로, 바퀴에 롤러가 달린 메카넘 휠(Mecanum wheel) 을 쓰면 옆으로도 미끄러지듯 이동할 수 있습니다. 이런 로봇은 홀로노믹(holonomic) 이라고 합니다. 창고 물류 로봇에서 흔히 보는 방식입니다.

로봇을 설계할 때 “홀로노믹이 가능한가”는 경로 계획 알고리즘의 선택을 바꿉니다. 논홀로노믹 로봇은 회전 반경을 고려한 경로(Dubins, Reeds-Shepp)가 필요하고, 홀로노믹 로봇은 더 자유로운 경로를 쓸 수 있습니다.

5. 토픽(Topic): 계속 흘러가는 데이터

개념

토픽은 발행자(Publisher)가 계속 내보내고, 구독자(Subscriber)가 받아보는 비동기 단방향 통신입니다. 라디오 방송과 같습니다.

  • 발행자는 누가 듣는지 모르고, 구독자는 누가 보내는지 몰라도 됨
  • 여러 발행자와 여러 구독자가 동시에 붙을 수 있음 (다대다)
  • 응답이라는 개념이 없음

목록 보기

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 topic list

/parameter_events
/rosout
/turtle1/cmd_vel
/turtle1/color_sensor
/turtle1/pose

타입까지 함께:

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 topic list -t

/turtle1/cmd_vel [geometry_msgs/msg/Twist]
/turtle1/pose [turtlesim/msg/Pose]

발행자/구독자 수와 QoS까지:

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 topic info /turtle1/cmd_vel --verbose

데이터 들여다보기

ros2 topic echo /turtle1/pose

x: 5.544445
y: 5.544445
theta: 0.0
linear_velocity: 0.0
angular_velocity: 0.0

거북이가 움직이면 값이 계속 갱신됩니다. Ctrl+C로 중단합니다.

발행 주기(Hz) 확인 — 센서 데이터가 정상 속도로 들어오는지 볼 때 유용합니다.

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 topic hz /turtle1/pose

average rate: 62.0

60Hz 내외라면 시뮬레이터가 정상 동작 중입니다. 실제 로봇에서는 “라이다가 10Hz로 와야 하는데 3Hz만 온다”는 식의 문제를 이 명령으로 잡습니다.

주행 명령 보내기: cmd_vel과 Twist

거북이를 움직이는 토픽은 /turtle1/cmd_vel이고, 타입은 geometry_msgs/msg/Twist입니다. 구조를 확인합니다.

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 interface show geometry_msgs/msg/Twist

Vector3 linear
Vector3 angular

Twist는 두 개의 벡터로 이루어집니다.

필드 의미 자동차 비유
linear 선속도 (m/s) 액셀·브레이크
angular 각속도 (rad/s) 핸들

각 벡터는 x, y, z 세 축으로 이루어집니다. 평면 로봇은 주로 linear.x(전진)와 angular.z(회전)를 씁니다.

한 번만 발행하기

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 1.8}}"
  • --once: 메시지를 한 번 보내고 종료
  • linear.x: 2.0 = 앞으로 2.0
  • angular.z: 1.8 = 반시계 방향으로 1.8 rad/s 회전

한 번만 보내면 거북이는 잠깐 움직이고 멈춥니다. 위에서 본 키보드 조작과 같은 이유입니다.

계속 움직이게 하기

⌨️ 입력 위치: 터미널 2 — 계속 발행 (멈추려면 Ctrl+C) · $ 뒤에 입력하고 Enter

ros2 topic pub --rate 1 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.8}}"
  • --rate 1: 1초에 1번 반복 발행
  • 값을 생략하면 0으로 채워집니다 (linear: {x: 2.0}만 써도 나머지는 0)

이제 거북이가 원을 그리며 계속 돕니다. Ctrl+C로 멈춥니다.

💡 실제 로봇에서 cmd_vel은 가장 중요한 토픽입니다. 자율주행 스택(Nav2)이 경로를 계산해 cmd_vel로 속도 명령을 내보내고, 베이스 드라이버가 이를 받아 바퀴를 돌립니다. 즉 ros2 topic pub으로 cmd_vel에 값을 넣는 것은 자율주행 스택이 하는 일을 손으로 흉내 내는 것입니다.

노드-토픽 관계를 그림으로

⌨️ 입력 위치: 터미널 2 · $ 뒤에 입력하고 Enter

rqt_graph

teleop_turtle → /turtle1/cmd_vel → turtlesim → /turtle1/pose 흐름이 그래프로 표시됩니다.

화면의 동그라미가 노드, 화살표 위의 글자가 토픽입니다. teleop_turtle → /turtle1/cmd_vel → turtlesim이 한눈에 보입니다. (출처: ROS 2 공식 문서, CC BY 4.0)

시스템이 복잡해질수록 이 그래프가 구명줄이 됩니다. “왜 로봇이 안 움직이지?” 싶을 때 rqt_graph를 열어 연결이 끊긴 지점을 찾는 것이 첫 단계입니다.

6. 액션(Action): 오래 걸리는 일의 진행 상황까지

서비스와 토픽의 한계

로봇에게 “여기서 10미터 앞까지 이동해”라고 명령한다고 합시다.

  • 서비스로 만들면: 도착할 때까지 아무 응답이 없다가, 끝나고 나서 “도착”만 돌아옵니다. 이동 중에 “지금 어디쯤인지”, “멈춘 건 아닌지” 알 수 없습니다.
  • 토픽으로 만들면: 명령을 흘려보내는 건 쉽지만, “이 작업이 끝났는가”를 알 방법이 없습니다.

이 간극을 메우는 것이 액션입니다.

구성 요소 역할
Goal(목표) “무엇을 하라”를 한 번 전달
Feedback(피드백) 진행 중 계속 전달되는 중간 상태
Result(결과) 작업이 끝났을 때 한 번 전달되는 최종 결과
Cancel(취소) 진행 중인 목표를 중단

액션은 서비스(목표/결과)와 토픽(피드백)을 조합한 구조입니다. 그리고 서비스와 달리 취소가 가능합니다.

타입 구조: 3단

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 action list -t

/turtle1/rotate_absolute [turtlesim/action/RotateAbsolute]

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 interface show turtlesim/action/RotateAbsolute

# The desired heading in radians
float32 theta
---
# The angular displacement in radians to the starting position
float32 delta
---
# The remaining rotation in radians
float32 remaining

서비스는 2단(요청/응답)이지만, 액션은 3단입니다.

구간 필드 의미
Goal theta 목표 방향(라디안)
Result delta 시작 자세로 돌아가기 위한 각도 변위
Feedback remaining 남은 회전량(라디안)

delta의 정의가 헷갈리기 쉽습니다. “시작 위치로 돌아가는 데 필요한 변위” 라서, 목표 각도와 부호가 반대로 나오는 경우가 많습니다. 공식 문서의 예제에서도 theta: 1.57을 보내면 delta: -1.568...이 돌아옵니다. “명령한 값과 결과가 왜 다르지?”가 아니라 정의가 다르다고 이해해야 합니다.

목표 보내기

⌨️ 입력 위치: 터미널 2 — 목표만 보내고 기다리는 예 · $ 뒤에 입력하고 Enter

ros2 action send_goal /turtle1/rotate_absolute turtlesim/action/RotateAbsolute "{theta: 1.57}"

Waiting for an action server to become available...
Sending goal:
  theta: 1.57

Goal accepted with ID: f8db8f44410849eaa93d3feb747dd444

Result:
  delta: -1.568000316619873

Goal finished with status: SUCCEEDED
  • Goal accepted with ID: ...: 모든 목표에는 고유 ID가 붙습니다. 어떤 목표를 취소할지 지정할 때 이 ID를 씁니다.
  • status: SUCCEEDED: 목표가 성공적으로 완료됨.

피드백 보기

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 action send_goal /turtle1/rotate_absolute turtlesim/action/RotateAbsolute "{theta: -1.57}" --feedback

Feedback:
  remaining: -3.1268...
Feedback:
  remaining: -3.1108...
...
Result:
  delta: 3.12...

remaining이 줄어드는 것을 보며 “지금 얼마나 남았는지” 를 실시간으로 알 수 있습니다. 이것이 액션을 쓰는 이유입니다.

취소

키보드 조작(turtle_teleop_key)에서 회전 키를 누른 뒤 F를 누르면 목표가 취소되고, 시뮬레이터 터미널에 다음과 같은 메시지가 나옵니다.

[INFO] [turtlesim]: Rotation goal canceled

실제 로봇에서 “취소”는 안전 기능입니다. 자율주행 로봇이 이동 중 장애물을 발견했을 때, 사람이 정지 버튼을 눌렀을 때, 배터리가 부족할 때 — 이런 상황에서 진행 중인 목표를 중단할 수 있어야 합니다.

액션 목록과 정보

⌨️ 입력 위치: 터미널 2 (명령용) · $ 뒤에 입력하고 Enter

ros2 action list
ros2 action list -t
ros2 action info /turtle1/rotate_absolute

Action: /turtle1/rotate_absolute
Action clients: 1
    /teleop_turtle
Action servers: 1
    /turtlesim

클라이언트(명령을 보내는 쪽)와 서버(수행하는 쪽)가 명확히 구분됩니다.

7. 네임스페이스: 같은 로봇 안에서 대상을 구분하기

서비스·토픽 이름 앞에 붙는 /turtle1/을 네임스페이스(Namespace) 라고 합니다.

/turtle1/cmd_vel      → 1번 거북이의 주행 명령
/turtle2/cmd_vel      → 2번 거북이의 주행 명령
/spawn                → 네임스페이스 없음 (전역)
/reset                → 네임스페이스 없음 (전역)

/spawn, /reset, /clear처럼 네임스페이스가 없는 서비스는 전체에 영향을 줍니다. 반면 /turtle1/...은 그 개체에만 적용됩니다.

/spawn으로 turtle2를 만든 뒤 ros2 service list를 다시 보면, turtle2/... 서비스가 새로 생긴 것을 확인할 수 있습니다.

도메인 vs 네임스페이스

구분 범위 목적
ROS_DOMAIN_ID 네트워크(장비) 단위 서로 다른 로봇/팀의 통신을 완전히 분리
네임스페이스 같은 도메인 안의 개체 단위 한 시스템 안에서 로봇별로 이름을 구분

둘은 대체 관계가 아니라 함께 쓰는 계층입니다.

[ROS_DOMAIN_ID = 13]  ← 팀 A의 네트워크
   ├── /robot1/...     ← 로봇 1
   └── /robot2/...     ← 로봇 2

다중 로봇 시스템에서는 이 두 계층을 함께 설계합니다. 도메인으로 “우리 팀”을 나누고, 네임스페이스로 “우리 팀 안의 로봇”을 나눕니다.

8. 세 통신 방식 비교

항목 토픽(Topic) 서비스(Service) 액션(Action)
패턴 발행-구독 요청-응답 목표-피드백-결과
동기/비동기 비동기 동기 비동기 + 진행 추적
연결 다대다 1:1 1:1 (클라이언트/서버)
응답 없음 있음 결과 + 중간 피드백
취소 — 불가 가능
적합한 일 센서 데이터, 주행 명령 순간 설정·조회 오래 걸리는 작업

계속 보내야 하면 토픽, 즉답이 필요하면 서비스, 시간이 걸리고 진행률이 필요하면 액션입니다.

실제 로봇에서의 대응

ROS 2 개념 실제 로봇에서
토픽 /cmd_vel 자율주행 스택이 바퀴에 속도 명령을 보냄
토픽 /scan, /image_raw, /imu 라이다·카메라·IMU 센서 데이터
토픽 /odom 바퀴 엔코더 기반 추정 위치
서비스 /spawn 같은 역할 시뮬레이터에서 로봇 생성, 그리퍼 열기/닫기 같은 단발 명령
액션 NavigateToPose (Nav2) “이 좌표로 이동해” — 진행률 피드백 + 취소
액션 FollowJointTrajectory 로봇팔 관절 궤적 실행

정리하면 “계속 흐르는 것 = 토픽”, “즉답이면 끝나는 것 = 서비스”, “오래 걸리고 중간 보고가 필요한 것 = 액션” 입니다. 로봇 개발에서 이 분류를 잘못하면, 나중에 “왜 진행률을 알 수 없지?” 같은 문제로 돌아옵니다.

9. 위치 오차와 허용 오차

액션 결과가 목표와 미세하게 다른 것을 볼 수 있습니다. theta: 1.57에 delta: -1.568...처럼 소수점 아래가 어긋나는 이유는 두 가지입니다.

  1. 정의 차이: delta는 “시작 자세로 돌아가는 변위”라서 부호와 기준이 다릅니다.
  2. 위치 추정 오차: 로봇은 자신의 위치를 센서 값으로 추정합니다. 100% 정확한 절대 위치를 아는 경우는 드뭅니다(실내에서는 GPS도 쓸 수 없습니다).

실제 로봇은 엔코더, IMU, 라이다, 카메라를 조합해 칼만 필터·파티클 필터 같은 알고리즘으로 “가장 그럴듯한 위치”를 계속 추정합니다. 바퀴가 미끄러지고, 마모되고, 바닥 마찰이 바뀌면 오차는 쌓입니다.

그래서 제어 시스템에는 허용 오차(tolerance) 가 있습니다.

"목표 지점에서 0.05m 이내에 들어오면 도착으로 간주"
"목표 각도에서 0.02rad 이내면 회전 완료로 간주"

나중에 배우게 될 SLAM(지도 작성과 위치 추정), AMCL(지도 기반 위치 추정), 센서 퓨전은 모두 이 “추정을 더 정확하게 만드는” 기술입니다. 터틀심의 소수점 오차는 그 세계의 아주 작은 예고편입니다.

10. 자주 겪는 문제

증상 원인 해결
ros2: command not found source 누락 새 터미널마다 source /opt/ros/jazzy/setup.bash
Package 'turtlesim' not found 미설치 sudo apt install ros-jazzy-turtlesim
ros2 run 했는데 아무 반응 없음 노드가 실행 중인데 GUI 창이 뒤에 있음 창 전환, ros2 node list로 확인
service call에서 타입 오류 서비스 타입 문자열 오타 ros2 service list -t로 정확한 타입 복사
토픽을 발행해도 안 움직임 토픽 이름/타입 불일치, --once만 보냄 ros2 topic list -t 확인, --rate로 반복 발행
키보드 조종이 안 됨 turtle_teleop_key 터미널이 비활성 해당 터미널 창을 클릭해 포커스
액션 결과가 목표와 다름 delta 정의 + 추정 오차 9장 참고 (정상 동작)
다른 사람 화면에 내 거북이가 보임 ROS_DOMAIN_ID 미설정 서로 다른 도메인 ID 지정
rqt_graph가 안 뜸 GUI 환경 아님 / rqt 미설치 데스크톱 세션에서 실행, sudo apt install ros-jazzy-rqt ros-jazzy-rqt-common-plugins

원인을 못 찾겠을 때는 rqt_console 을 열어 보세요. 모든 노드의 로그(INFO·WARN·ERROR)가 한 창에 모입니다.

아래 Exclude Messages / Highlight Messages에서 severities: Debug Info Warn Error Fatal을 지정해 원하는 로그만 남길 수 있습니다. (출처: ROS 2 공식 문서, CC BY 4.0)

11. 정리

⌨️ 입력 위치: 터미널 2 · $ 뒤에 입력하고 Enter

# 노드
ros2 node list
ros2 node info /turtlesim

# 서비스
ros2 service list -t
ros2 service type /turtle1/teleport_absolute
ros2 interface show turtlesim/srv/Spawn
ros2 service call /spawn turtlesim/srv/Spawn "{x: 2.0, y: 2.0, theta: 0.2, name: ''}"

# 토픽
ros2 topic list -t
ros2 topic echo /turtle1/pose
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 1.8}}"

# 액션
ros2 action list -t
ros2 interface show turtlesim/action/RotateAbsolute
ros2 action send_goal /turtle1/rotate_absolute turtlesim/action/RotateAbsolute "{theta: 1.57}" --feedback

# 구조 확인
rqt_graph
  • 노드는 기능 단위 프로그램, 패키지는 그 묶음입니다.
  • 서비스는 요청-응답(1:1, 동기), 토픽은 발행-구독(다대다, 비동기), 액션은 목표-피드백-결과(+취소)입니다.
  • 네임스페이스로 개체를 구분하고, ROS_DOMAIN_ID 로 네트워크를 분리합니다.
  • 로봇의 자세는 x, y, theta로 표현되고, 각도는 라디안을 씁니다.

여기까지 오면 로봇 개발의 기본 어휘를 모두 손에 넣은 것입니다. 이제 남은 것은 이 어휘로 실제 로봇을 움직이는 일입니다 — 센서 데이터를 받아 처리하고, 경로를 계획하고, 모터에 명령을 내리는 노드를 직접 작성하는 단계입니다.

이 글에 나온 명령어·기호 풀이

ros2 명령은 ros2 <무엇을> <동사> <대상> 구조로 읽으면 쉽습니다. 예: ros2 topic echo /turtle1/pose = “ros2야, 토픽을, 출력해, /turtle1/pose 를”.

표기 원래 말 / 읽는 법 하는 일
ros2 run 패키지 실행파일 run 노드(프로그램) 실행
ros2 pkg executables 패키지 package 그 패키지가 가진 실행 파일 목록
ros2 node list — 지금 떠 있는 노드 목록
ros2 node info /이름 — 그 노드의 토픽·서비스·액션을 자세히
ros2 service list -t — 서비스 목록 + 타입(-t = --show-types)
ros2 service type /이름 — 그 서비스의 타입 이름만
ros2 service call /이름 타입 "{값}" call 서비스를 호출
ros2 interface show 타입 — 그 타입의 필드 구조를 보여 줌
ros2 topic list -t — 토픽 목록 + 타입
ros2 topic info /이름 --verbose — 발행자·구독자까지 자세히
ros2 topic echo /이름 — 토픽에 흐르는 데이터를 계속 출력 (Ctrl+C 로 중단)
ros2 topic hz /이름 hertz 초당 몇 번 오는지(주기) 측정
ros2 topic pub /이름 타입 "{값}" publish 토픽으로 데이터를 발행
--once — 한 번만 발행
--rate 1 — 1초에 1번씩 계속 발행
ros2 action list -t — 액션 목록 + 타입
ros2 action send_goal /이름 타입 "{값}" — 액션에 목표를 보냄
--feedback — 진행 상황(중간 피드백)까지 출력
{x: 2.0, y: 2.0, theta: 0.0} — 목표 값을 따옴표로 감싼 YAML 형식
theta (θ) — 로봇이 바라보는 각도 (라디안)
radian — 각도 단위. π = 180°, 1.57 ≈ 90°
x, y — 화면의 가로·세로 위치 (미터)
cmd_vel command velocity 속도 명령 토픽 (linear=앞뒤, angular=회전)
rqt_graph — 노드·토픽 연결 그래프
/turtle1/... — 네임스페이스가 붙은 이름 (거북이 1번의 것)
Ctrl+C — 실행 중인 명령(계속 발행·출력) 중단

값이 {...} 로 들어가는 명령은 중괄호와 따옴표를 그대로 입력해야 합니다. 따옴표를 빼면 셸이 먼저 해석해 오류가 납니다.
