파이썬으로 로봇을 다루다 보면 반드시 한 번은 만나는 지옥이 있습니다.

> "어제까지 잘 돌던 코드가 오늘 갑자기 안 됩니다."

원인의 대부분은 **라이브러리 버전 충돌**입니다. 어떤 프로젝트는 `numpy 1.x`를 요구하고, 다른 프로젝트는 `numpy 2.x`를 요구합니다. 한 컴퓨터에 파이썬을 하나만 두고 전부 설치하면, 두 요구를 동시에 만족시킬 수 없습니다.

이 글은 그 문제를 근본적으로 막는 **파이썬 가상환경(venv)** 을 다룹니다. 로봇 프로젝트는 라이브러리 의존성이 유난히 복잡하기 때문에, 이 습관 하나가 이후 몇 달의 디버깅 시간을 결정합니다.

이 글에서 다루는 것

- 가상환경이 왜 필요한지, 무엇을 격리하는지
- 우분투 24.04의 시스템 파이썬과 `externally-managed-environment` 오류
- `venv` 생성·활성화·종료의 정확한 명령
- 가상환경 안에서 pip 관리하기, `requirements.txt`로 재현하기
- 로봇 프로젝트에서 쓰는 폴더 구조와 주의점

## 명령은 어디에 입력하나요?

이 글의 명령은 **터미널**에서 입력합니다. 다만 2편부터는 **"어느 터미널이냐"** 가 중요해집니다.

**여는 방법**: 바탕화면에서 `Ctrl` + `Alt` + `T` (또는 앱 표시 → Terminal)

**이 글에서 구분하는 세 가지 상태**

| 표시 | 뜻 | 이 글에서 |
| --- | --- | --- |
| `user@robot-pc:~$` | 일반 터미널, 시스템 파이썬을 씀 | 가상환경 **만들 때** |
| `(robot_venv) user@robot-pc:~$` | 가상환경이 **켜진** 터미널 | 패키지 설치·실행할 때 |
| `deactivate` 후 | 다시 일반 상태로 돌아옴 | 작업이 끝났을 때 |

- 프롬프트 앞의 `(robot_venv)` 가 **"지금 이 창은 가상환경 안"** 이라는 표시입니다.
- 같은 명령이라도 활성화 전/후에 결과가 달라지므로, 코드 블록마다 **어느 상태에서 치는지** 적어 두었습니다.
- 복사는 `Ctrl`+`Shift`+`C`, 붙여넣기는 `Ctrl`+`Shift`+`V` 입니다.

## 한눈에 보는 전체 흐름: 만들고 → 켜고 → 설치

![가상환경 만드는 순서 — 생성, 활성화, 설치, 비활성화](https://velog.velcdn.com/images/aiexcelh/post/532ebc00-2395-4af6-a327-967cd70e3f9b/image.png)

*만들기는 프로젝트마다 한 번, 활성화는 터미널을 열 때마다입니다.*

1. **폴더 이동** — `cd ~/robot_ws`
2. **생성** — `python3 -m venv .venv`
3. **활성화** — `source .venv/bin/activate` (프롬프트에 `(.venv)` 표시)
4. **설치** — `pip install numpy opencv-python`
5. **종료** — `deactivate`

## 1. 가상환경이 격리하는 것

파이썬은 패키지를 **site-packages** 라는 디렉터리에 설치합니다. 가상환경은 이 디렉터리를 **프로젝트별로 따로** 만들어 줍니다.

```text
[가상환경 없이]
시스템 파이썬 (하나)
  └─ site-packages: numpy 2.x, opencv 4.10, ...

[가상환경 사용]
시스템 파이썬 (건드리지 않음)
  ├─ ~/venv/robot_venv   → numpy 2.x, opencv 4.10
  └─ ~/venv/vision_venv  → numpy 1.26, opencv 4.5
```

가상환경은 시스템 파이썬을 **기반으로 하되**, 패키지 공간(`site-packages`)만 따로 가집니다. 아래는 실제 편집기 화면에서 이 관계가 어떻게 보이는지입니다.

![VS Code의 Select Interpreter 목록 — 프로젝트 폴더의 venv가 Recommended로 표시된다](https://velog.velcdn.com/images/aiexcelh/post/8184da0f-d499-403a-a53f-bede82796d05/image.png)

*VS Code 공식 문서의 실제 화면입니다. 목록 맨 위 `Python 3.10.5 ('venv': venv) … Recommended`가 **이 프로젝트의 가상환경**이고, 그 아래 `Global`/`Conda` 항목이 시스템에 깔린 다른 파이썬입니다. 가상환경을 쓰면 편집기도 이렇게 "프로젝트 전용 인터프리터"를 구분해서 보여 줍니다. (출처: VS Code 공식 문서, CC BY 3.0)*

핵심은 세 가지입니다.

1. **프로젝트마다 다른 버전을 쓸 수 있습니다.**
2. **시스템(운영체제)이 쓰는 파이썬을 건드리지 않습니다.** 우분투 자체도 파이썬으로 만들어진 도구를 쓰기 때문에, 시스템 파이썬을 망가뜨리면 OS 업데이트나 GUI 도구가 깨질 수 있습니다.
3. **환경을 지우고 다시 만들 수 있습니다.** 가상환경은 "재생 가능한 소모품"입니다. 이상해지면 폴더째 지우고 다시 만들면 됩니다.

> 공식 문서에서는 가상환경을 "프로젝트에 필요한 특정 파이썬 인터프리터와 라이브러리를 담는 디렉터리"로 설명하며, **소스 관리(Git)에 넣지 말고**, **옮기거나 복사하지 말고 필요하면 다시 만들라**고 안내합니다.

### 로봇 개발에서 왜 유난히 중요한가

로봇 소프트웨어는 다음 같은 라이브러리를 함께 씁니다.

- 수치 연산: `numpy`, `scipy`
- 영상 처리: `opencv-python`
- 딥러닝: `torch`, `onnxruntime`
- 로봇 통신: `rclpy`(ROS 2), `pymodbus`, `pyserial`

이들은 서로 촘촘하게 물려 있습니다. 예를 들어 `opencv-python`의 특정 버전은 `numpy`의 상한 버전을 요구하고, `torch`는 또 다른 조합을 요구합니다. 시스템 전체에 하나의 조합만 두면, 새 라이브러리를 하나 설치할 때 기존 프로젝트가 깨집니다.

## 2. 우분투 24.04의 시스템 파이썬: 함부로 pip install 하지 마세요

우분투 24.04는 **Python 3.12**를 기본으로 제공합니다. 그런데 여기서 `pip install`을 그냥 실행하면 다음과 같은 오류를 만나게 됩니다.

*⌨️ 입력 위치: 터미널(일반 상태) — 일부러 실패를 보는 예 · `$` 뒤에 입력하고 `Enter`*

```bash
pip3 install requests
```

```text
error: externally-managed-environment

× This environment is externally managed
╰─> To install Python packages system-wide, try apt install
    python3-xyz, where xyz is the package you are trying to install.
    ...
note: If you believe this is a mistake, please contact your Python installation
or OS distribution provider. You can override this, at the risk of breaking
your Python installation or OS, by passing --break-system-packages.
```

이것은 고장이 아니라 **보호 장치**입니다. PEP 668은 배포판이 "이 파이썬의 패키지는 OS 패키지 관리자가 관리한다"고 선언할 수 있게 만든 표준이고, 우분투는 이 정책을 켜 두었습니다. 목적은 명확합니다.

- `pip`로 설치한 패키지가 OS가 설치한 패키지를 덮어써서 시스템 도구를 망가뜨리는 것을 막음
- 대신 **가상환경을 쓰도록** 유도

### 그래서 선택지는 세 가지

| 상황 | 권장 방법 |
| --- | --- |
| 프로젝트용 라이브러리 설치 | **가상환경(venv) 안에서** `pip install` |
| OS 전역에 필요한 도구 | `sudo apt install python3-패키지명` |
| CLI 도구 하나만 설치 | `pipx` (도구별 가상환경을 자동 관리) |

`--break-system-packages` 옵션은 표준 문서에도 "위험을 감수하고 우회"하는 플래그로 정의되어 있습니다. **시스템 파이썬에는 가급적 쓰지 마세요.** 정말 필요한 상황(격리된 컨테이너, 일회성 CI 등)이 아니라면, 가상환경을 만드는 편이 언제나 낫습니다.

> 💡 시스템 파이썬 버전은 언제든 확인할 수 있습니다.
>
> ```bash
> python3 --version
> # Python 3.12.x
> ```

## 3. 준비: 필요한 도구 확인

### pip 확인

*⌨️ 입력 위치: 터미널(일반 상태) · `$` 뒤에 입력하고 `Enter`*

```bash
pip3 --version
```

`command not found`가 나오면 설치합니다.

```bash
sudo apt update
sudo apt install python3-pip
```

### venv 도구 확인

우분투에서는 `venv` 구성 요소가 기본 이미지에 항상 들어 있지는 않습니다. 아래 명령이 실패하면 해당 패키지를 설치합니다.

*⌨️ 입력 위치: 터미널(일반 상태) · `$` 뒤에 입력하고 `Enter`*

```bash
# 파이썬 버전에 맞는 venv 패키지 설치 (Ubuntu 24.04 기준)
sudo apt install python3.12-venv
```

> 버전이 다른 우분투(예: 22.04)라면 `python3.10-venv`처럼 버전을 맞춰야 합니다. `python3 -m venv`가 "ensurepip is not available" 같은 메시지로 실패하면 이 패키지가 빠진 것입니다.

## 4. 가상환경 만들기

먼저 가상환경을 모아 둘 폴더를 만듭니다. 프로젝트마다 흩어지지 않게 **한 곳에 모으는 것**이 관리에 유리합니다.

*⌨️ 입력 위치: 터미널(일반 상태) · `$` 뒤에 입력하고 `Enter`*

```bash
cd ~
mkdir -p venv
ls
```

이제 가상환경을 생성합니다.

*⌨️ 입력 위치: 터미널(일반 상태) · `$` 뒤에 입력하고 `Enter`*

```bash
python3 -m venv ~/venv/robot_venv
```

- `-m venv`: `venv` 모듈을 실행하라는 뜻
- 뒤의 경로: 생성할 디렉터리 (없으면 만들어 줍니다)

생성된 구조는 대략 이렇습니다.

```text
~/venv/robot_venv/
├── bin/
│   ├── python      # 이 환경의 파이썬 (시스템 파이썬을 가리킴)
│   ├── pip
│   └── activate    # 활성화 스크립트
├── include/
├── lib/python3.12/site-packages/   # 이 환경 전용 패키지 저장소
└── pyvenv.cfg
```

> `pyvenv.cfg`에는 이 환경이 어느 파이썬을 기반으로 만들어졌는지(`home`)가 기록됩니다. 가상환경을 옮기면 이 경로가 깨지기 때문에, 공식 문서가 "이동·복사하지 말라"고 하는 것입니다.

## 5. 활성화와 종료

### 활성화

*⌨️ 입력 위치: 터미널 — 가상환경을 켜는 명령 · `$` 뒤에 입력하고 `Enter`*

```bash
source ~/venv/robot_venv/bin/activate
```

활성화되면 프롬프트 앞에 환경 이름이 붙습니다.

```text
(robot_venv) user@robot-pc:~$
```

이 표시가 **"지금 내가 가상환경 안에 있다"는 유일한 확실한 신호**입니다. 작업 전에 항상 확인하는 습관을 들이세요.

확인 명령:

*⌨️ 입력 위치: 터미널 — 방금 활성화한 창에서 · `$` 뒤에 입력하고 `Enter`*

```bash
which python
# /home/user/venv/robot_venv/bin/python

python -c "import sys; print(sys.prefix)"
```

`which python`이 가상환경 경로를 가리키면 정상입니다.

### 종료

*⌨️ 입력 위치: 터미널 — 가상환경이 켜진 창에서 · `$` 뒤에 입력하고 `Enter`*

```bash
deactivate
```

프롬프트의 `(robot_venv)`가 사라지고 원래 시스템 셸로 돌아옵니다.

> 💡 **새 터미널을 열면 활성화는 풀립니다.** 터미널마다 셸이 새로 뜨기 때문입니다(0편). 터미널을 새로 열 때마다 `source .../activate`를 다시 실행해야 합니다. 이 반복이 싫다면 5편의 `alias`를 활용하세요.

## 6. 가상환경 안에서 pip 관리하기

가상환경을 켠 상태에서는 `pip`가 **그 환경의 site-packages**만 바라봅니다. 이때는 `--break-system-packages` 없이 자유롭게 설치할 수 있습니다.

*⌨️ 입력 위치: 터미널 — **`.venv` 가 켜진 상태**에서 · `$` 뒤에 입력하고 `Enter`*

```bash
# 가상환경 안에서 pip 자체를 최신으로
python -m pip install --upgrade pip

# 패키지 설치
python -m pip install numpy opencv-python
```

> `pip` 대신 `python -m pip`를 쓰는 이유: `pip` 실행 파일이 여러 개 있을 때 **현재 파이썬에 확실히 묶인 pip**를 쓰기 위해서입니다. 환경이 꼬였을 때 원인 파악이 쉬워집니다.

환경을 만들 때 pip까지 최신으로 맞추고 싶다면 생성 옵션을 쓸 수 있습니다.

*⌨️ 입력 위치: 터미널(일반 상태) · `$` 뒤에 입력하고 `Enter`*

```bash
python3 -m venv --upgrade-deps ~/venv/robot_venv
```

> `--upgrade-deps`는 venv 생성 시 pip 등 핵심 의존성을 최신으로 올려 줍니다(공식 문서의 `venv` 옵션). 단, Python 3.12부터는 `setuptools`가 venv의 기본 구성 요소에서 빠졌으므로, `setup.py` 기반 패키지를 다룬다면 별도로 설치해야 할 수 있습니다.

## 7. 환경을 "재현"하는 법: requirements.txt

가상환경 폴더 자체는 Git에 올리지 않습니다. 대신 **어떤 패키지의 어떤 버전을 설치했는지**를 파일로 남깁니다.

*⌨️ 입력 위치: 터미널 — **가상환경이 켜진 상태**에서 · `$` 뒤에 입력하고 `Enter`*

```bash
# 현재 환경의 패키지 목록 저장
python -m pip freeze > requirements.txt
```

```text
numpy==2.1.3
opencv-python==4.10.0.84
```

다른 PC(또는 나중의 나)에서 같은 환경을 복원:

*⌨️ 입력 위치: 터미널 — 가상환경을 켜는 명령 · `$` 뒤에 입력하고 `Enter`*

```bash
python3 -m venv ~/venv/robot_venv
source ~/venv/robot_venv/bin/activate
python -m pip install -r requirements.txt
```

> 왜 폴더를 복사하지 않나? 가상환경은 절대 경로와 OS·파이썬 버전에 묶여 있어서, 복사해도 제대로 동작하지 않는 경우가 많습니다. **"만드는 방법"을 저장하는 것**이 정석입니다.

`.gitignore`에 다음을 넣어 두면 실수로 환경이 커밋되는 것을 막을 수 있습니다.

```text
venv/
.venv/
__pycache__/
```

## 8. 로봇 프로젝트에서의 실전 팁

### (1) 환경 이름은 용도로 짓기

| 이름 | 용도 |
| --- | --- |
| `robot_venv` | 로봇 제어 기본 실습용 |
| `vision_venv` | 영상 처리·딥러닝 |
| `sim_venv` | 시뮬레이터 전용 |

### (2) 작업 시작 전 3초 점검

*⌨️ 입력 위치: 터미널 — 방금 활성화한 창에서 · `$` 뒤에 입력하고 `Enter`*

```bash
echo $VIRTUAL_ENV     # 비어 있으면 활성화 안 된 상태
which python
```

`$VIRTUAL_ENV`는 가상환경이 활성화될 때 자동으로 설정되는 환경변수입니다.

### (3) 전역 오염을 의심하는 신호

- `which python`이 `/usr/bin/python3`를 가리킨다 → 활성화가 풀렸다
- `pip list`에 설치한 적 없는 패키지가 잔뜩 있다 → 시스템 pip를 보고 있다
- 패키지를 설치했는데 `import`가 안 된다 → 다른 파이썬(다른 환경)에 설치됐다

### (4) ROS 2와 함께 쓸 때

ROS 2의 파이썬 패키지(`rclpy` 등)는 우분투 패키지로 설치되며, `source /opt/ros/jazzy/setup.bash`가 관련 경로를 `PYTHONPATH`에 넣어 줍니다. 즉 **가상환경을 쓰더라도 ROS 2 환경은 별도로 유지**됩니다.

여기서 주의할 점이 있습니다.

- 같은 라이브러리(예: `numpy`)를 양쪽에서 서로 다른 버전으로 요구하면, 어느 쪽이 먼저 인식되는지에 따라 동작이 달라질 수 있습니다.
- ROS 2 노드를 개발할 때는 **버전을 고정**(`requirements.txt`)하고, 문제가 생기면 `python -c "import numpy; print(numpy.__version__)"`로 실제 로드된 버전을 확인하세요.
- 시스템 패키지와 섞어 쓰는 것이 부담스럽다면, ROS 2 개발은 시스템 파이썬 기준으로 두고 **딥러닝·영상처리만 별도 가상환경**으로 분리하는 구성도 흔히 씁니다.

### (5) venv vs conda, 뭘 쓰나

| 항목 | `venv` (표준 라이브러리) | `conda` (Anaconda/Miniconda) |
| --- | --- | --- |
| 설치 | 파이썬에 기본 포함 | 별도 설치 필요 |
| 패키지 출처 | PyPI (`pip`) | conda 채널 + PyPI |
| 강점 | 가볍고 표준, OS 파이썬과 궁합이 명확 | 파이썬이 아닌 바이너리 의존성(CUDA 등)까지 관리 |
| 추천 | 일반 프로젝트, ROS 2 연동 | 딥러닝 환경을 여러 개 격리할 때 |

처음 시작한다면 **venv로 충분**합니다. 딥러닝 프레임워크 버전을 여러 개 오가며 실험해야 할 때 conda를 고려하면 됩니다.

## 9. 자주 겪는 문제

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `externally-managed-environment` | 시스템 파이썬에 직접 설치 시도 | 가상환경 활성화 후 설치 |
| `ensurepip is not available` | venv 패키지 미설치 | `sudo apt install python3.12-venv` |
| 활성화했는데 `pip`가 시스템 것을 씀 | PATH 우선순위/활성화 풀림 | `which pip`, `which python` 확인 |
| `deactivate`가 없다고 나옴 | 활성화 상태가 아님 | 프롬프트의 `(환경명)` 확인 |
| 패키지 설치 후에도 `import` 실패 | 다른 환경에 설치됨 | `python -m pip install ...`로 현재 파이썬 지정 |
| 환경을 지웠더니 프로젝트가 안 됨 | venv 폴더 삭제 | `requirements.txt`로 재생성 |

## 10. 정리

- 파이썬 라이브러리 충돌은 **프로젝트별 격리**로 막습니다.
- 우분투 24.04의 시스템 파이썬은 **PEP 668로 보호**되어 있어 `pip install`이 거부됩니다. 우회하지 말고 가상환경을 쓰세요.
- 핵심 명령은 네 개입니다.

*⌨️ 입력 위치: 터미널 — 가상환경을 켜는 명령 · `$` 뒤에 입력하고 `Enter`*

```bash
python3 -m venv ~/venv/robot_venv          # 생성
source ~/venv/robot_venv/bin/activate      # 활성화
deactivate                                  # 종료
python -m pip freeze > requirements.txt     # 기록
```

다음 글에서는 이 가상환경을 **VS Code에 연결**합니다. 편집기에서 코드를 실행할 때 "어느 파이썬으로 실행되는지"가 명확해지면, 라이브러리 문제의 절반이 사라집니다.

## 이 글에 나온 명령어·기호 풀이

| 표기 | 원래 말 / 읽는 법 | 하는 일 |
| --- | --- | --- |
| `python3` | — | 우분투의 파이썬 3 실행 파일 |
| `pip3` | **p**ip **i**nstalls **p**ackages | 파이썬 패키지 설치 도구 |
| `python3 --version` | — | 파이썬 버전 확인 |
| `pip3 --version` | — | pip 버전과 **어느 파이썬에 붙어 있는지** 확인 |
| `-m` | **m**odule | "모듈을 스크립트처럼 실행" 옵션 (`python3 -m venv` = venv 모듈 실행) |
| `venv` | **v**irtual **env**ironment | 파이썬 표준 가상환경 만들기 모듈 |
| `~/venv/robot_venv` | — | 가상환경을 만들 **경로**(폴더) |
| `source` | — | 스크립트를 **현재 셸에서** 실행 (환경변수 적용) |
| `activate` | — | 가상환경을 **켜는** 스크립트 (`bin/activate`) |
| `(robot_venv)` | — | 프롬프트 앞 표시 = **가상환경이 켜져 있음** |
| `deactivate` | — | 가상환경을 **끄고** 시스템 파이썬으로 복귀 |
| `which python` | — | `python` 이라는 명령이 **실제로 어느 파일**인지 보여 줌 |
| `pip install 패키지` | — | 패키지 설치 |
| `pip install -r requirements.txt` | `-r` = **r**equirement file | 파일에 적힌 목록을 **한 번에** 설치 |
| `pip freeze` | — | 현재 설치된 패키지와 버전을 **목록으로** 출력 |
| `> requirements.txt` | 리다이렉션 | 그 목록을 파일로 저장 |
| `--upgrade-deps` | — | `pip`·`setuptools` 같은 기본 도구까지 최신으로 |
| `echo $VIRTUAL_ENV` | — | 가상환경 경로 변수 출력 (**비어 있으면 꺼진 상태**) |
| `sudo apt install python3.12-venv` | — | 파이썬 버전에 맞는 venv 도구 설치 |
| `externally-managed-environment` | — | "시스템 파이썬은 보호 중" 이라는 우분투 24.04의 **오류 메시지** (정상 동작) |

> `pip` 와 `pip3` 는 같은 도구입니다. 우분투에서는 `pip3` 라는 이름이 함께 등록되어 있어, `pip` 가 없으면 `pip3` 를 쓰면 됩니다.
